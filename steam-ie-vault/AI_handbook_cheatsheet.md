### 1. Architectural & Core LLM Mechanics

#### The CPU/RAM/Storage Analogy [59]
*   **LLM as CPU:** 
    *   **Definition:** The Large Language Model itself, which functions as the central processor of the AI system [59].
    *   **Description:** It handles raw computation, logical inference, and code generation based on user prompts and session context [59, 60]. This is akin to writing in a very high-level language where English commands are translated into executable computer code [60].
*   **Context Window as RAM:**
    *   **Definition:** The immediate, high-speed active memory buffer of an LLM [60, 61].
    *   **Description:** The context window determines how much code and textual metadata the model can process simultaneously in a single turn [62]. Larger context sizes directly improve the model's ability to maintain logical consistency and understand holistic system interactions [62, 63].
*   **External Knowledge as Long-Term Storage:**
    *   **Definition:** External documentation, files, or vector repositories that the AI fetches data from [61].
    *   **Description:** When an AI retrieves data from a repository, wiki, or database, it is analogous to a standard CPU fetching data from a solid-state hard drive [61, 62].

#### Context Window Size [62]
*   **Definition:** The maximum number of tokens an LLM can parse and hold in working memory at any one time [62].
*   **Description:** Early models (e.g., GPT-3.5 Turbo) possessed context windows of 16k tokens, whereas modern systems scale up to 2 million tokens (e.g., Gemini 1.5 Pro) [68, 69]. Large windows enable a model to digest entire multi-file codebases, configuration tables, and documentation simultaneously to solve non-isolated, system-level issues [69, 70].
*   **Performance/Cost Factors:** Processing massive context windows is computationally expensive (e.g., GPT-4 costing $30 per million tokens) [64, 68]. However, modern optimized models like Claude 3.5 Sonnet balance large contexts (200k tokens) with high coding intelligence (92.0 HumanEval score) at a lower cost ($3 per million tokens) [65, 68, 69].

#### Retrieval-Augmented Generation (RAG) [72]
*   **Definition:** A data retrieval pattern that dynamically extracts highly relevant blocks of information from an external database and injects them directly into the LLM's active context window [72].
*   **Description:** While large context windows technically permit loading entire codebases, doing so for every single routine query is cost-prohibitive [72, 73]. RAG mitigates this by selectively querying matching file segments [73].
*   **Context-Building Approaches:** 
    *   *Currently Open Files:* Feeding the tabs actively open in the IDE [74].
    *   *IntelliSense Dependency Understanding:* Automatically tracking import hierarchies and including related dependencies [75].
    *   *Semi-Automatic Selection:* Allowing developers to review and approve files or headers suggested by the AI [75].
    *   *Cascade with Small Language Models (SLMs):* Employing a cheap, fast SLM to skim the codebase first and isolate target files to forward to a larger model [76].
    *   *Agentic Code Exploration:* Enabling an AI agent to read headers and systematically traverse files step-by-step as needed [76].
    *   *Vector Search:* Performing semantic mathematical search across pre-computed code embeddings [76].

#### Hallucinations [78]
*   **Definition:** The generation of incorrect, non-existent, or fabricated facts, methods, or syntax presented with confident assurance [78].
*   **Description:** Hallucinations stem from the probabilistic nature of LLMs, which predict next tokens without possessing a deterministic model of factual truth [78]. In code generation, this may appear as non-existent parameters or deprecated library methods (e.g., inserting a phantom `order` parameter into a pandas interpolation method) [79].
*   *Fail-Safe Advantage:* Unlike legal or medical fields, coding hallucinations generally carry a low operational risk because they trigger immediate warnings in modern IDEs or fail-fast compilation errors during execution [79, 80].

#### HumanEval [63]
*   **Definition:** A standardized software engineering benchmark used to evaluate the functional correctness of coding models on Python-based tasks [63, 69].
*   **Description:** It measures performance based on the model's ability to successfully write code that passes specific unit tests [63, 69].

### 3. Prompting & Customization Techniques

#### Custom Instructions [81, 82]
*   **Definition:** Sticky configurations that persist across chat sessions to pre-define the system's persona, format rules, and architectural constraints [82, 83].
*   **Description:** It eliminates the overhead of repeating boilerplate context (e.g., preferred tech stack, styling rules, or brevity guidelines) in every prompt [83, 84, 85]. This is particularly valuable for project-specific assistants or specialized translators [83, 84].

#### Custom GPTs & Claude Projects [131, 143]
*   **Custom GPTs (OpenAI):**
    *   **Definition:** Tailored conversational assistants created on ChatGPT that use vector-based RAG to search uploaded knowledge bases [131, 134].
    *   **Description:** By querying files via selective RAG search, they handle large file bases while conserving message quotas [132, 134]. However, selective retrieval may occasionally miss deep contextual details, and they lack API access to update code repositories automatically [134, 135].
*   **Claude Projects (Anthropic):**
    *   **Definition:** Targeted workspace environments on Claude that load uploaded documentation directly into the model's primary active context window [143, 144].
    *   **Description:** This results in deeper conceptual synthesis and highly accurate code alignment [144]. However, loading entire files consumes context tokens rapidly, which can deplete message quotas faster [144, 145].

#### Claude Artifacts [148]
*   **Definition:** A dedicated visual sub-panel in the Claude interface that displays, runs, and versions structured, non-conversational code, spreadsheets, or graphics [148].
*   **Description:** Artifacts allow developers to inspect and interact with complete code outputs (such as React components, Tailwind styles, or Mermaid diagram designs) without cluttering the chat window [149]. The visual sandbox runs on a pre-installed, secure environment featuring TypeScript, Tailwind, and React [149].

### 14. Advanced Cognitive Architectures

#### System 1 vs. System 2 Thinking (Fast vs. Slow Thinking) [484]
*   **Fast Thinking (System 1):**
    *   **Definition:** Rapid, intuitive output generation based on pattern recognition [484].
    *   **Description:** Standard LLM behavior where text is generated incrementally token-by-token without logical pauses [484].
*   **Slow Thinking (System 2):**
    *   **Definition:** Deliberate, analytical reasoning that decomposes problems before generating output [484].
    *   **Description:** Pioneered by models like OpenAI o1, this model performs multi-step self-reflection behind the scenes [484, 485].

#### Hidden Chain-of-Thought (CoT) & Graph-of-Thought (GoT) [485]
*   **Hidden Chain-of-Thought:** Model reasoning steps executed in secret to evaluate, split, and refine intermediate solutions before delivering a final response [485].
*   **Graph-of-Thought:** An advanced cognitive concept where an AI builds and navigates dynamic mental maps to track branching decisions and recover from logic errors [485].

#### Scale and Inference Scaling Laws [486]
*   **Definition:** The principle that AI model intelligence scales not just with training data, but with the amount of time and compute spent during inference (thinking time) [486].
*   **Description:** Instead of instantly returning a response, giving a model like o1 time to think can yield major logic improvements [486, 488].
