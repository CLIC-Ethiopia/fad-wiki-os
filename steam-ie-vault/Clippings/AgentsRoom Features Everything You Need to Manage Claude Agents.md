Process Guard

## The runaway process finder for AI coding agents

An AI agent spawns a real system process for every tool call it makes: a search, a build, a script. Most finish in seconds, some never do, and those keep holding gigabytes of RAM at 0% CPU until the machine crawls. On one measured session, seven stuck processes claimed 41.8 GB on a 16 GB laptop, swap sat at 95%, and ending them returned 15.5 GB instantly. Process Guard sweeps the child processes of your agents once a minute and flags one only when it is large, old AND idle on the processor, so a real build is never mistaken for a stuck one. It measures the true memory footprint, compressed and swapped-out pages included, because a stuck process can show 20 MB while holding 8 GB. Orphaned processes that outlived their agent are caught too. Your dev command terminals, the shell and the agent CLI itself are never touched, and nothing is terminated unless you ask.

## Secrets your agents can use but never read

API keys, tokens and passwords live in a machine-local vault encrypted through your OS keychain, in a single file written owner-only and atomically. You reference a secret by name, and AgentsRoom resolves it at launch, in the main process, into the environment of the command being started. An agent can list the names and ask for one to be injected, and there is no code path that returns a value to an agent, to the interface or over MCP. Nothing is synced to a server, and a machine without a usable keychain gets a refusal rather than a file in clear text.

## Reach an RDS database in a private subnet, without a bastion

Your Amazon RDS instance has no public endpoint, no inbound SSH and a security group that only lets the application in. AgentsRoom reaches it through an AWS Systems Manager port-forwarding session: it asks the operating system for a free loopback port, runs aws ssm start-session with the AWS-StartPortForwardingSessionToRemoteHost document through a managed EC2 node, and waits until that port really accepts a TCP connection before connecting its database client. No bastion host to patch, no VPN to provision, no endpoint and password copied into a chat message. Authorization comes from the AWS profile already configured on your machine, so no key is stored by the app, and the forwarded port is bound to 127.0.0.1 only. MySQL, PostgreSQL and MongoDB, so RDS MySQL, RDS PostgreSQL, Aurora and DocumentDB.
